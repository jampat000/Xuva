## Summary

Completes the remaining items from issue #129 that were not included in PR #131.

**Server changes:**
- `MovieListItem` and `SeriesListItem` now include `addedAt` (ISO timestamp from `created_at`) and `watched` (bool, aggregated from `playback_states` via the requesting user's session)
- `ListMovies` / `ListSeries` accept a `userID string` parameter; SQL LEFT JOINs through `movie_versions` / `episode_versions` → `playback_states` so watch state is per-user and zero-cost when unauthenticated (empty user ID matches no rows)
- Updated all callers: `moviesHandler`, `seriesHandler`, `clientHomeHandler` in `router.go`; `metadata/service.go` batch refresh; all catalog and api test files

**Frontend changes:**
- `browse.ts`: `addedAt?`, `watched?` on both list interfaces; `needsReview?` formally typed on `SeriesListItem`
- `mock-data.ts`: `addedAt?`, `watched?`, `studio?` on `Media`
- `adapters.ts`: maps `addedAt`, `watched`, `studio[]` (movies: `metadata.studios`; series: `metadata.networks ?? metadata.studios`)
- `LibraryGrid`: 2 new sort modes (Date Added Newest/Oldest); 3 new filter sections: Studio multi-select chips (top 20 by count, hidden when empty), Watched/Unwatched segmented toggle (hidden when no watch data), Missing Metadata flag toggle (hidden when not applicable); URL params `studios`, `watch`, `missing`
