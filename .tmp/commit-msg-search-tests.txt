test(search): cover SearchLibrary and clientSearchHandler

Adds unit tests for the search code shipped in PR #75 (0bf0692):

catalog.SearchLibrary
- empty query yields empty buckets with non-nil slices
- no-match query yields empty buckets
- a single query populates movies/series/people/collections together
- limit defaults to 8, custom limit honored, hard-capped at 40
- scoring order: exact > prefix > word-prefix > contains
- people deduplicated by name with creditCount aggregated across movies
- collections deduplicated by id with movieCount aggregated

api.clientSearchHandler
- happy path returns 200 with the documented {query,movies,series,people,
  collections} shape and the right per-kind fields (kind/id/title/name/...)
- default limit of 8 applied when ?limit is omitted
- explicit ?limit is respected and clamped to 40 when above
- empty ?q returns HTTP 200 with empty buckets (handler chooses 200 over
  400 so the client's debounced typeahead never has to special-case)
